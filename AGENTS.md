# Project instructions

## Keep the wiki current

- After every project change, review and update `wiki.md` in the same work unit before considering the task complete.
- Keep `wiki.md` aligned with the actual current implementation, including changes to behavior, normalization stages, UI/UX, APIs, configuration, storage, deployment, tests, and operational limitations.
- Update the document status date or schema/version references whenever they become stale.
- Do not describe planned behavior as implemented behavior. When a change does not alter the product contract, still record any relevant maintenance or operational consequence in `wiki.md`.
